About

From a business classroom to a Linux terminal — same instinct, different tools.

I studied Business Administration at Alexandria University, on the Management Information Systems track — a mix of marketing, accounting, business ethics and organisational management, alongside an introduction to networking and programming. That mix is where I first noticed I cared less about the business case and more about the systems running underneath it.

Before graduating, I looked through most of the tech tracks available to MIS students before settling on DevOps. It's the one place where you're not just building one piece — you're responsible for the environment everything else runs in. That appealed to me immediately.

I applied to the ITI scholarship right after graduation and made it to the interview stage, but wasn't accepted. Instead of waiting for the next intake, I built my own path: Linux first, then Bash scripting, then networking fundamentals, then Python — each one chosen because a DevOps engineer actually needs it, not because a course told me to learn it.

On the cloud side, I started with the concepts behind VMware before moving to AWS, where I wanted hands-on practice before the theory — so I worked through AWS Cloud Quest, earned the Cloud Practitioner training badge, and later sat the official AWS Certified Cloud Practitioner exam.

Project

A real deployment, done the long way on purpose

For my first project, I skipped Docker deliberately. I wanted to feel every manual step before reaching for a tool that hides them — so the convenience would mean something once I got there.

Application Python · Flask · HTML / CSS / JavaScript front end
App server Gunicorn, to handle real traffic load
Web server Nginx as reverse proxy, for smooth request handling
Process management Custom systemd unit, so the app survives reboots and crashes
Version control Git and GitHub for the full history of the build
Infrastructure AWS EC2 (t2.micro), provisioned and managed from my own terminal
By design No Docker, no containers — manual setup first, so the next step actually saves time instead of just feeling modern
